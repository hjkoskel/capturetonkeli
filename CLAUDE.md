# CLAUDE.md – capturetonkeli

USB dongle (Seeed XIAO ESP32-C5) that captures and filters 802.11 frames in promiscuous mode and streams them over USB to a browser UI (Web Serial / WebUSB) or a Go CLI. Specs live in `docs/` (01–13). **Read the relevant spec before changing anything.** When code and spec disagree, the spec wins until it is deliberately updated.

## Repo facts
- `index.html` at the repo root is the live GitHub Pages site (`https://<owner>.github.io/capturetonkeli/`). `main` = production. Never push to `main` directly; use PRs.
- **Web UI:** vanilla HTML/CSS/JS only. No frameworks, no npm packages, no build step, no CDN, no external URLs. All paths **relative** (the site lives under `/capturetonkeli/`).
- `fw/` is generated by `make release`. Never edit it by hand; CI verifies it byte-for-byte against a rebuild.
- **Go:** module root = repo root. Library in `ctp/`, CLI in `cmd/ctpbench/`, conformance suite in `conformance/`. **Stdlib only** (no `require` in go.mod).
- **Firmware:** `firmware/`, C11, ESP-IDF pinned in `firmware/idf-version.txt`. Never change the pin to match a local IDF; ask the user.
- Shared golden vectors in `testvectors/` are generated by Go (`go generate ./...`) and consumed by Go, JS and C tests.

## Order of work for any protocol change
1. Update docs/03 (and bump the version per docs/03 §11: MAJOR for breaking changes, MINOR for new fields/messages/behaviour, PATCH for fixes).
2. Update the Go reference (`ctp/`) and simulator, then `go generate ./...` to refresh `testvectors/`.
3. The C core passes the new vectors on host (`make host-test fw-host-conf`).
4. Hardware-in-the-loop (`make fw flash hil`).
5. Web UI (test against demo mode / Go simulator first).

## Firmware rules (docs/07 §4, docs/10)
- Core logic lives in `firmware/components/ctp_core` and must not include ESP-IDF or FreeRTOS headers.
- Change core → `make host-test fw-host-conf` must pass before touching hardware.
- Never cast wire bytes to structs; use the `rd.c` cursors. No malloc after init. No recursion, no VLAs. Warnings are errors. No `assert()`; use `CTP_ASSERT`.
- Core must compile as both C11 and C23 (IDF v6 defaults to gnu23).
- IDF v6 pitfalls:
  - use `WIFI_BW20`/`WIFI_BW40` (not `*_HT20/HT40`);
  - never use `WIFI_BAND_MODE_AUTO`;
  - call `esp_wifi_init` once;
  - include `freertos/FreeRTOS.h` explicitly before driver headers;
  - **never touch GPIO13/14 or the USB PHY** (it breaks USB flashing).
- New IDF symbol → add it to `firmware/idf-api.txt` (feeds the API smoke build).
- Zero flash writes at runtime: Wi-Fi NVS off, country kept in RAM, PHY calibration not stored.
- Build: `make fw` uses native IDF if it matches the pin, else Podman with the pinned image. Flashing always runs on the host.

## Firmware / hardware dev loop (docs/06 §6)
1. Build: `make fw`
2. Flash: `make flash` (= `ctpbench fw flash --manifest firmware/build/manifest.json --yes`: REBOOT 1 → ROM → differential write → MD5 verify → watchdog reset → HELLO; ~5 s if unchanged, ~13 s full). If interrupted, just rerun it. If the port is busy: `ctpbench doctor`.
   - Do **not** use plain `idf.py flash` / esptool's default DTR/RTS reset, never toggle DTR/RTS, and never send CTP bytes to a chip in ROM mode: each wedged the C5 until replugged (docs/10 §3). Recovery: ask the user to replug (holding BOOT if needed), then `make flash`.
   - The port can move between `/dev/ttyACM0` and `ACM1` after a reset; use `--port auto` (default).
   Release/HIL machines: `ctpbench fw ensure --yes` before testing.
3. Smoke: `ctpbench info --json`
4. Verify: `ctpbench conformance --skip CTP-FLT-RF --traffic-country FI --traffic-channel 13 --json --out-dir bench-out/last` (exit 0 = pass; pick a busy channel)
5. On failure read only `bench-out/last/report.json`; follow each failed case's `hint` and its `.trace.jsonl`.
6. Performance changes: `make fw-synth flash-synth` (synthetic-traffic variant, no radio), then `ctpbench bench throughput --json --compare-baseline usb` and `ctpbench bench rtt-under-load`; reflash the normal build with `make fw flash` afterwards. Baseline copy: docs/measurements/throughput-usb-v6.0.2.json (bench-out/ is git-ignored).

- Without hardware use `--port sim` (the Go simulator is the reference behaviour) or `make fw-host-conf` (real firmware core on a PTY).
- Exit code 9 = firmware MAJOR.MINOR mismatch: **never** pass `--allow-fw-mismatch` on your own; update the dongle or ask the user.
- Never run `ctpbench inject` (it transmits) unless the user asks.
- Anything that writes flash needs `--yes`; without it ctpbench prints the plan only.

## Local web development
- `make serve`: dev server on the whole lab LAN (http; USB works only as http://localhost on this machine). `make serve-https`: same with a self-signed certificate (bench-out/serve-cert/, git-ignored) so other lab machines and phones get Web Serial/WebUSB after accepting the warning once. Or the UI's demo mode ("Try without hardware").
